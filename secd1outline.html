1.1 Compare and Contrast Various Types of Security Controls

+

Security Control Categories

Technical Controls

Controls implemented using systems and technology

Examples:
  • Operating system controls
  • Firewalls and intrusion prevention systems
  • Antivirus software
  • Encryption systems
  • Access control systems
  • Authentication mechanisms
Managerial Controls

Administrative controls associated with security design and implementation

Examples:
  • Security policies and procedures
  • Standard operating procedures (SOPs)
  • Security awareness training programs
  • Risk assessments and audits
  • Business continuity planning
  • Incident response procedures
Operational Controls

Controls implemented by people rather than technical systems

Examples:
  • Security guards and personnel
  • Background checks and screening
  • Security awareness training execution
  • Physical access monitoring
  • Media handling procedures
  • Configuration management
Physical Controls

Controls that protect physical assets and facilities

Examples:
  • Locks, doors, and barriers
  • Security cameras and surveillance
  • Biometric scanners
  • Environmental controls (HVAC)
  • Secure disposal methods
  • Visitor management systems

Security Control Types

Preventive Controls

Purpose: Stop security incidents before they occur

Examples: Firewalls, access controls, encryption, security awareness training

Deterrent Controls

Purpose: Discourage potential attackers from attempting an attack

Examples: Warning signs, visible security cameras, security guards, legal penalties

Detective Controls

Purpose: Identify and alert when security incidents occur

Examples: Intrusion detection systems (IDS), log monitoring, security cameras, motion sensors

Corrective Controls

Purpose: Respond to and remediate security incidents after detection

Examples: Incident response procedures, patch management, malware removal, system restoration

Compensating Controls

Purpose: Provide alternative protection when primary controls are unavailable

Examples: Manual processes when automated systems fail, additional monitoring when encryption isn't possible

Directive Controls

Purpose: Guide and direct behavior through policies and procedures

Examples: Security policies, acceptable use policies, compliance requirements, training mandates

1.2 Summarize Fundamental Security Concepts

+

CIA Triad (Confidentiality, Integrity, Availability)

Confidentiality

Definition: Preventing disclosure of information to unauthorized individuals or systems

Implementation Methods:
  • Encryption of data at rest and in transit
  • Access controls and permissions
  • Two-factor authentication (2FA/MFA)
  • Data classification and handling procedures
  • Network segmentation
Integrity

Definition: Ensuring data is stored and transferred as intended; detecting unauthorized modifications

Implementation Methods:
  • Hashing algorithms (SHA-256, MD5)
  • Digital signatures
  • Checksums and cyclic redundancy checks (CRC)
  • Version control systems
  • Access controls to prevent unauthorized changes
Availability

Definition: Ensuring systems and data are accessible when needed by authorized users

Implementation Methods:
  • Redundancy and fault tolerance
  • Load balancing and clustering
  • Regular system maintenance and patching
  • Disaster recovery planning
  • Uninterruptible power supplies (UPS)

Non-Repudiation

Definition: Proof that an action or event cannot be denied by involved parties

Implementation: Digital signatures, audit logs, timestamping, certificate authorities

Authentication, Authorization, and Accounting (AAA)

Authentication

Purpose: Verifying identity of users or systems

  • Authenticating People: Passwords, biometrics, smart cards, tokens
  • Authenticating Systems: Digital certificates, shared secrets, cryptographic keys
Authorization

Purpose: Determining what authenticated users can access or do

  • Role-based access control (RBAC)
  • Discretionary access control (DAC)
  • Mandatory access control (MAC)
  • Attribute-based access control (ABAC)
Accounting

Purpose: Tracking user activities and resource usage

Components: Audit logs, session tracking, resource monitoring, compliance reporting

Zero Trust Architecture

Control Plane Components
  • Adaptive Identity: Real-time validation based on user behavior, device, and location
  • Threat Scope Reduction: Limiting access to minimize attack surface
  • Policy-Driven Access Control: Role and responsibility-based access policies
  • Policy Administrator: Manages and enforces access policies
  • Policy Engine: Makes access decisions based on policies and real-time data
Data Plane Components
  • Implicit Trust Zones: Segments where similar trust levels exist
  • Subject/System: Entities requesting access to resources
  • Policy Enforcement Point: Where access decisions are implemented

Deception and Disruption Technology

Honeypots

Purpose: Decoy systems designed to attract and analyze attackers

Benefits: Early threat detection, attacker behavior analysis, threat intelligence gathering

Honeynets

Purpose: Networks of multiple honeypots simulating complete environments

Benefits: Comprehensive attack analysis, network-level threat intelligence

Honeyfiles

Purpose: Fake files designed to detect unauthorized access

Benefits: Internal threat detection, data access monitoring

Honeytokens

Purpose: Fake data elements that trigger alerts when accessed

Benefits: Breach detection, insider threat identification

1.3 Explain the Importance of Change Management Processes

+

Business Processes Impacting Security Operations

Approval Process
  • Formal authorization requirements before implementing changes
  • Change control board (CCB) review and approval
  • Documentation of change justification and impact assessment
Ownership
  • Clear identification of change owners and responsible parties
  • Accountability for change success and rollback if needed
  • Process management and stakeholder communication
Impact Analysis
  • Assessment of potential effects on security posture
  • Risk evaluation and mitigation planning
  • Dependencies and integration considerations
Test Results
  • Validation of changes in controlled environments
  • Security testing and vulnerability assessments
  • Performance and functionality verification
Backout Plan
  • Detailed procedures for reversing changes if problems occur
  • Rollback timelines and decision criteria
  • Recovery procedures and data restoration

Technical Implications

Allow Lists/Deny Lists
  • Allow Lists: Only approved applications/processes can execute (more restrictive)
  • Deny Lists: Blocked applications/processes cannot execute (less restrictive)
  • Security policy enforcement through application control
Downtime Considerations
  • Service Restart: Interruption of individual services
  • Application Restart: Application-level interruptions
  • System Downtime: Complete system unavailability

1.4 Explain the Importance of Using Appropriate Cryptographic Solutions

+

Public Key Infrastructure (PKI)

Core Components
  • Public Key: Freely distributable key for encryption and signature verification
  • Private Key: Secret key for decryption and digital signing
  • Key Escrow: Secure storage of private keys for recovery purposes
PKI Trust Models
  • Hierarchical Trust Model: Single root CA with subordinate CAs
  • Distributed Trust Model: Multiple CAs with cross-certification
  • Bridge Trust Model: Central authority facilitating CA interconnection

Encryption Technologies

Encryption Levels
  • Full-Disk Encryption: Complete drive encryption (BitLocker, FileVault)
  • Partition Encryption: Specific disk partition protection
  • File-Level Encryption: Individual file protection
  • Database Encryption: Database-specific encryption (TDE)
  • Record-Level Encryption: Individual database record protection
Encryption Types
Symmetric Encryption:
  • Single shared key (AES, DES, 3DES)
  • Fast processing, efficient for large data
  • Key distribution challenges
Asymmetric Encryption:
  • Public/private key pairs (RSA, ECC)
  • Solves key distribution problem
  • Slower processing, used for key exchange

Cryptographic Tools

Hardware Security Modules (HSM)
  • Dedicated cryptographic processors
  • Secure key generation and storage
  • Hardware-based random number generation
  • Tamper-resistant/tamper-evident design
Trusted Platform Module (TPM)
  • Hardware-based security chip on motherboards
  • Secure boot process verification
  • Cryptographic key storage and generation
  • Platform integrity measurements

Hashing and Digital Signatures

Hashing Functions
  • Purpose: Data integrity verification and digital fingerprinting
  • Algorithms: SHA-256, SHA-3, MD5 (deprecated), BLAKE2
  • Properties: Fixed output size, avalanche effect, irreversibility
Digital Signatures
  • Hash encryption with private key for authentication
  • Non-repudiation and integrity verification
  • DSA, RSA, ECDSA signature algorithms
  • Time-stamping for temporal verification

Exam Preparation Tips

+

Key Focus Areas

  • Understand the relationship between different security control types and categories
  • Master the CIA Triad and its practical implementations
  • Learn Zero Trust architecture components and benefits
  • Comprehend change management processes and their security implications
  • Understand PKI components and certificate management
  • Study encryption types, algorithms, and appropriate use cases

Common Exam Scenarios

  • Selecting appropriate security controls for given situations
  • Identifying physical security measures for different environments
  • Analyzing change management process failures and improvements
  • Choosing correct cryptographic solutions for specific requirements
  • Understanding certificate validation and trust relationships

Study Recommendations

  • Practice with virtual labs for hands-on experience
  • Review real-world case studies of security implementations
  • Use flashcards for memorizing cryptographic algorithms and key lengths
  • Practice scenario-based questions for application of concepts
  • Focus on the "why" behind security implementations, not just the "what"
